# LightBurn ⇄ NEJE 5 Plus over Bluetooth

把 NEJE 5 Plus 通过**蓝牙**接到 LightBurn，并获得**接近 USB 直连的完整体验** ——
不是「导出 GCode 再上传」的半套方案，而是 LightBurn 里**直接按 Start**。

```
LightBurn ──TCP 127.0.0.1:4002──> 本程序 ──BLE──> NEJE 5 Plus
```

LightBurn 需要一个串口，而 NEJE 只提供蓝牙；本程序在两者之间做一条**透明字节管道**，
让 LightBurn 以为自己在跟一台串口 GRBL 设备说话。

## 快速开始

```sh
# 1) 依赖（只需要一个）
python3 -m pip install bleak

# 2) 一键启动（零参数、零配置）
python3 tools/neje.py
```

然后在 LightBurn 里新建/选择一个 **TCP** 设备：地址 `127.0.0.1`、端口 `4002`。
连接后照常使用：**Start 自己的设计、回零、点动、改设置、读位置**。

macOS 上也可以**双击 `neje.command`**（等价于上面那条命令）。

### 三种运行方式

```sh
python3 tools/neje.py          # 完整功能：激光已供电，准备出光
python3 tools/neje.py --test   # 激光物理隔离：安全试跑（不会出光）
python3 tools/neje.py --check  # 启动前检查设备是否处于 GRBL 模式
```

**会话结束时程序会自动对本次通信做独立审计并打印结论**（是否丢字节、是否伪造设备回应、
是否重放、是否干净收尾）。出现异常时会明确标出并提示保留捕获。

## 安全（请务必先读）

**这是一台会出光的激光设备。**

- **只有设备自身的电源开关能真正停下它。** 已实测：主机侧的软件停止、干净断开、
  无线链路突然消失**都停不住**；失联时设备会把已经收到的作业执行到底。
- 出光前确认：**护目镜（455nm 蓝光）· 通风 · 灭火设备在手边 · 能随时切断设备主电源 ·
  行程净空 · 手离开机器**。
- **首次出光务必先慢。** 实测对照（同一会话、同一功率 S100/10%）：

  | 速度 | 结果 |
  | --- | --- |
  | 300 mm/min（5 mm/s） | ✅ **痕迹明显** |
  | 6000 mm/min（100 mm/s） | ❌ 无痕（9mm 的线只跑 0.09 秒） |

- 急停：`python3 tools/emergency_stop.py --execute --log <新日志>`
  （只发 `!`、`0x85`、`0x18` 三个实时字节，不重试；复位后坐标不可信，需重新回零）
- 详见[日常使用指南](docs/daily-use-guide.md)与[首次出光方案](docs/level-e-test-plan.md)。

## 设计取舍（值得知道）

**1. 透明优先，但不猜测。** 透明模式下客户端的 GRBL 字节被**原样转发**，没有作业审阅、
没有白名单。唯一的例外是被实测证明危险的命令 —— 见下条。

**2. 点动 `$J=` 会被翻译，不原样转发。** 实测发现该固件把 `$J=` 当作**绝对目标**执行：
从 `X0` 出发的 `$J=X1F100` 与「相对 +1mm」不可区分（所以看着正常），
而从 `Y400` 出发的 `$J=Y-1F100` 意味着「移到 Y=−1」—— **401mm 的行程**，
机器因此失控跑飞。现在它被翻译成一条**显式的有界相对移动**：

```
$J=Y-1F100   →   G91 G1 Y-1 F100
```

意图完全一致、**一行进一行出**（`ok` 数量不变，不影响 LightBurn 的流控），
而相对位移**在结构上不可能跑飞**。真机验证：±1.000mm 精确、移动后稳定停住。
含模态/设置字、步长 >100mm、缺进给或进给越界的点动仍会被拒绝。

**3. 回零用整轴 `$H`。** 实测 `$HX`/`$HY`（轴选择性）在此固件上**只回 `ok` 却不建立位置**；
整轴 `$H` 才真正回零。旧形式保留为 `--axis-selective-home`，仅用于复现实验。

**4. 绝不伪造。** 桥接不会伪造 `ok`、状态报告或计数器；不重放、不自动重连到状态未知的设备。
每个会话都写完整日志，并可被独立审计。

## 架构

| 组件 | 作用 |
| --- | --- |
| `tools/neje.py` | **一键入口**：装配参数、启动桥接、结束时自动审计 |
| `tools/pipeline_tcp_bridge.py` | TCP ⇄ BLE 桥接；`--transparent` 为透明模式 |
| `tools/passthrough_policy.py` | 透明策略：原样转发 + 点动翻译 + 畸形拒绝 |
| `tools/emergency_stop.py` | 一键急停（实时字节，不重试） |
| `tools/check_transparent_capture.py` | 独立审计：字节守恒、防伪造、无重放、干净收尾 |
| `tools/homing_recovery_probe.py` | 受审回零（整轴 `$H`） |
| `tools/status_panel.py` | 图形化只读状态面板（不连接设备） |

NEJE 的私有传输层：`FF | AA/AB | len | group<<4|ver | subcmd | data | 0x55/CRC32`，
GRBL 数据走可靠组 `0x40`（`03` 写 / `04` 读，带 16 位滚动字节计数）。

## 已知边界

- **桥接会话是单客户端、一次性的**：LightBurn 断开重连后需重新启动一次
  （这样每次连接都从一次干净的初始化开始，避免重入未知状态）。
- **点动不是字节透传**（会被翻译，理由见上）。
- 控制器报告的 `FS:<进给>,<功率>` 中功率字段恒为 0 —— 该固件不用它上报激光功率，
  因此**是否出光只能靠现场目视**，不要用软件读数代替你的眼睛。
- 修改设备设置（`$n=value`）会**持久化写入**设备，且不随断电恢复。
