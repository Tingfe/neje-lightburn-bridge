# 原生透明桥接当前方案

> 2026-10-14 的设计记录。现行结构与能力边界请先看[工作原理](architecture.md)，当前验收看[状态页](overall-progress.md)。下文的“后续”按记录日期理解。

2026-10-14。透明模式已由外部工具实现并完成真实 LightBurn 作业；本轮继续完善同一路径。用户再次明确核心目标是透明桥接，以完整使用 LightBurn 功能。[本轮结果](native-transparent-hardening-result.md)取代旧“未实施”口径。

LightBurn 直接生成并发送作业，不要求导出、摘要或白名单。`PassthroughPolicy`只做换行和实时字节分流，保留原生 `$J`；`TransparentGrblPipeline`维护有限输入额度、真实终端归属与停止代际；NEJE可靠通道核验帧、CRC与计数。受审文件模式保持独立测试用途。

原生 GRBL 命令由固件执行并返回真实结果：包括作业、点动、`$H`、`$X`、坐标偏移、设置读写、暂停恢复及实时倍率。桥接不以 G91 G1 替代点动。Alarm 初始状态允许原生恢复查询/命令；正在运行的未知作业不会被新会话直接接管。

软件复位优先于未发送数据：同一接收块中的其他字节及本机旧队列被废弃；实际复位横幅与新鲜Idle/Alarm必须到达，才记录复位确认。1.2.0保留健康TCP/BLE连接，允许真实横幅之后的新初始化，旧作业不重放；确认不表示停止距离已经物理测量或位置重新可信。故障、未知清理或复位后的会话退出仍不自动另起连接。断连本身不停止已缓冲运动。见[Stop兼容修复](lightburn-image-and-stop-result.md)。

交付使用方式、传输限制和真实验收缺口见 [README](../README.md)。后续优先验证当前透明版本的原生相对点动及模态保持、运动中暂停/Stop/恢复，再做 BLE 数小时连续运行和对焦/材料受控的 USB 加工效果对照。旧受审捕获继续保留，不冒充当前透明版本的完整验收。
