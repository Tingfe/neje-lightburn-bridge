# 透明桥接方案：让 LightBurn 通过蓝牙获得「USB 直连等效」能力

2026-10-13。**状态：方案，未实施。** 本文件说明要改什么、会失去什么保证、保留什么保证，以及实施与验证步骤。**在你逐项确认之前不会动代码。**

## 1. 目标能力（USB 直连时能做的，桥接也要能做）

| 能力 | 现状 | 目标 |
| --- | --- | --- |
| 任意设计直接 Start（无需先导出、无需预审） | ❌ 逐字节比对受审文件 | ✅ 原样转发 |
| 点动 / Move 面板（`$J=`） | ❌ 不在白名单 | ✅ |
| 回零（`$H`） | ❌ 不在白名单 | ✅ |
| 设置工作原点 / 偏移（`G10`、`G92`） | ❌ | ✅ |
| 读位置 / 状态、跑作业、暂停恢复停止 | ⚠️ 受控路径 | ✅ |
| 改设备设置（`$n=value`） | ❌ 明确拒绝 | ✅（见第 3 节风险） |

## 2. 要改什么（技术上其实更简单）

**核心：去掉「作业比对」，改成透明字节管道。**

| 现在 | 透明模式 |
| --- | --- |
| 客户端字节必须逐行等于受审作业 | **客户端字节原样转发** |
| 初始化白名单（`$I`/`?`/`$#`/`G0`/`$$`） | **白名单取消**，任意 GRBL 字节通过 |
| 受控流水线 + `ControlledJobPolicy` | **改用直通策略**（`GrblPipeline` 已具备字节流↔NEJE 帧映射与计数器完整性） |

保留不变的底层机制（这些是「能工作」的前提，不是安全闸门）：

- NEJE 私有帧封装（`Write`/`ReadFrom`，16 位滚动字节计数）
- 可靠通道使能（`ENABLE_BLE_RELIABLE`）
- 设备响应**原样**回传，**绝不伪造 `ok`/状态**
- 单客户端、一次性会话、**不自动重连、不重放**
- 有界缓冲与计数器完整性校验

## 3. 会失去什么保证（请逐条确认你接受）

1. **不再有预先审阅**：任何 GCode 都会被转发。文件里的坐标越界、功率过高、模态错误，**桥接不再拦截**，只由设备自己的固件行为决定。
2. **出光随时可能发生**：LightBurn 里任何会出光的操作（含误操作、误开的图稿）都会真实出光。必须保持激光供电隔离时才绝对安全 —— 但那样就无法真实加工。
3. **点动无界**：`$J=` 的距离不再受桥接限制，撞框风险回归到「设备固件 + 你的操作」。
4. **改设置会写进设备**：`$n=value` 会真实持久化，可能改变行程/加速度/激光模式等，且**不随断电恢复**。
5. **实测过的残酷事实仍然成立**：**只有设备自身的电源能真正停下机器**。软件停止、干净断开、无线失联都停不住它；失联时设备会把已收到的作业执行到底。

**换句话说：透明模式之后，安全责任回到操作者与设备固件，和 USB 直连时完全一样。** 这正是你要的等效性，也是它的代价。

## 4. 保留的保证（一定不省）

| 保证 | 理由 |
| --- | --- |
| 不伪造 `ok`/状态/计数器 | 伪造会掩盖真实故障；这是本项目一贯底线 |
| 不重放、不自动重连 | 重放＝重复加工；自动重连＝重入未知状态 |
| 响应原样、顺序不变 | LightBurn 依赖终端序列做流控 |
| 计数器完整性校验 | 传输必须能发现丢字节 |
| 原始字节全量记录 | 出事后能复盘 |
| 缓冲区有界 | 防内存无限增长 |

## 5. 实施步骤

1. 新增 `--transparent` 模式（**独立开关，默认仍是现有受审模式**，互不影响）。
2. 直通策略：客户端字节不做作业比对；白名单取消。
3. 保留现有 `GrblPipeline`/`ControlledGrblPipeline` 的帧与计数器机制。
4. 审计：新增 `check_transparent_capture.py`，断言「双向字节与 NEJE 帧一一对应、无伪造终端、无重放、计数连续」。
5. 测试：合成捕获（含丢失/重复/越界计数）＋离线回环。
6. 真机验证顺序：
   - a. 只读（`?`、`$#`、`$G`）→ 确认与 USB 直连读数一致；
   - b. **零功率**点动（如 `$J=X1F100`）→ 现场确认移动量与方向；
   - c. 回零 `$H` → 确认终点 X0/Y400；
   - d. 零功率小作业 Start → 与 USB 直连的字节/行为对照；
   - e. **最后**才是真实出光加工，且先小功率单段。

## 7. 与现有目标的关系

现有 99/100 的评分体系建立在受审模式之上；**透明模式是并行的第二条通路**，不改变已归档的证据与结论。它是「LightBurn 全功能日常使用」这条目标线的实现方式。
