# 管理入口：显式通道恢复与只读控制器核查

2026-10-13，E86起。上一目标轮E84–E85为progress：4007条长文件两端实机及管理文件入口通过。本轮补齐常见完整行断连后的管理恢复，不缩小USB等效目标。

`lightburn_session.py recover`默认只显示离线计划。实际执行需已有故障/孤立running状态、同根目录实际进程锁可取得、当前session_id与目录匹配、完整原始通知/帧及写入/核验计数证明。记录目标BLE地址，拒绝不同地址。扫描、计数及当前身份不匹配即停止，不接管其他路由。

复用已有独立拥有路由检查：同一设备model55/app3，允许way0或所属way2，写计数只能在最后核验点或单个未核验GATT块全部接受处，读变化最多1024字节；三次状态稳定、无传输错误后，至多关闭一次并读回way0/app3及不变计数。

按实际接受字节判断GRBL行边界；设备可能保留半行时，不发送查询、换行、复位或运动，保留启动阻止，需另行处理清空输入和定位。已发生复位的捕获也不直接认定坐标可信。此判断借鉴固定版本gnea/grbl protocol.c/serial.c，NEJE半行保留不能仅由上游源码推定已实测。

完整边界下才另行建立一次受限BLE读取连接，精确发送 `? / $$ / $G / $# / $N / ?`，无运动、复位、解锁、回零或设置写入。两次真实Idle/X0/Y400/Z/A0/FS0,0、毫米/绝对/G54、M5/S0、零偏移、当前260×400行程和空启动块均满足；完整CRC/计数/真实响应及关闭的独立审计通过，才将顶层指针标为recovered、允许后续另行start。原失败session.json和bridge.jsonl不修改，原作业仍为unknown、不追认完成。

先验证真实历史原始帧篡改、进程锁、半行、计数变化、非零功率及完整模拟生命周期。随后在既有sessions根目录，用真实LightBurn仅初始化，在真实$I应答后的一次GetStatus交换中由独立实验程序请求真实BLE断开。等待管理进程失败/锁释放，核验直接start拒绝，再执行recover；恢复后单独start一次真实初始化并正常关闭，证明用户可继续使用。没有载入作业、不运动、不出光，不重复请求既有范围许可。异常不重复故障注入、不绕过故障锁。
