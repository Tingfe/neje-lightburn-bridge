# E67：可复用 LightBurn 会话入口候选

2026-10-13。上一轮E66补齐了USB／BLE停止独立审计和当前Pi基线包，本轮继续推进最终目标的日常使用入口。新增 `tools/lightburn_session.py`：review、start、status三个入口，默认离线预览；实际启动复用已有桥接和所有文件/控制/隔离门槛，自动生成独立会话目录、固定摘要作业副本、原始日志和结束审计，并保留跨进程故障状态。使用方法见[操作说明](lightburn-managed-session-guide.md)。

## 复用现有实现

对 `pipeline_tcp_bridge.py` 只提取纯参数解析 `parse_args(argv=None)`、令main接受显式参数列表；原有CLI行为、范围门槛、源文件审阅、发送/接收/控制核心不变。新入口直接调用同一进程中的原桥接main，不另建一套协议层或伪造控制器响应。

沿用已归档固定GRBL/cncjs传输原则及项目原始CRC/可靠计数、普通行账本和独立审计：文件正常完成由check_controlled_capture核验，初始化由check_pipeline_tcp_capture核验。启动器的日志/互斥/状态记录是本轮新增本机流程代码，未声称从开源项目复制该部分。

## 行为和限制

默认review/start不连接BLE、不创建sessions目录；status只读已有状态。实际启动先验证原入口的全部权限门槛，然后为作业保存摘要相同的job.gc副本。所有旧授权次数和几何范围保持原样，不自动添加授权标志。

每次会话原始日志独立创建；同一会话根目录用fcntl进程锁互斥，状态JSON通过临时文件、fsync及原子替换保存。连接后失败、审计不通过、Ctrl-C或遗留running状态阻止下一次直接启动。不依据旧PID消失或本机计数归零清除远端未知状态。没有自动重连、自动重试、自动恢复或“清空故障”按钮。仅在捕获明确表明没有进入TCP/BLE会话时区分未使用或连接前失败，保留其非作业成功结论。

自动审计当前限定正常完成；控制实验沿用专门实验工具和范围，管理入口不把暂停/停止当作本次正常作业授权。该入口及同一session-root以外的旧工具不由此统一封锁；不声称全机安全锁。Windows未适配，当前面向Mac/Linux开发环境。
