# 流水核心接入实际 LightBurn：初始化与正常退出

2026-10-12，新增`tools/pipeline_tcp_bridge.py`将GRBL流水核心接入Mac原生BLE→TCP→实际LightBurn。仍是明确的初始化白名单：`$I`、`$#`、裸`G0`、实时`?`和原始空行/注释。它不接受作业运动、出光、回零、设置写入、复位或暂停/恢复。没有复用已消费的运动授权。

## 接入方式与边界

TCP原始行字节进入有限队列，普通行按真实终端ACK释放发送额度；实时状态字节不消耗普通行ACK额度。接收预算来自真实Idle/FS0/Bf报告：1500减8为1492，GATT载荷上限173。没有套用标准128字节缓冲，也没有伪造ok。LightBurn自身发送窗口保持。

保留`?\n`产生的普通空行及其真实ok对应关系。EOF后不再启动排队行或实时字节；对已尝试发送的应答做最多2秒的只接收收尾，实际收到但不再发送给退出客户端的数据有独立日志。非法/未完成输入、异常/断链/超时停止，无自动重发、重连或续跑。

初始化解析器现在可由明确空作业列表构造；原固定1mm解析器默认序列保持，旧捕获审计继续通过。此变更不意味着用户授权通用运动。`GrblPipeline.step(receive_only=True)`不会消费任何未发送普通行或实时队列，已有状态/ACK仍可核验。

E45共有206完整帧，11字节系统通知尾部未完成，没有用于查询、清理或任何应答；E44有642完整帧及35字节系统尾部。两轮终点均是控制器报告；本轮没有运动，所以不能新增机械位移验收。

原始/严格审计位于`evidence/pipeline-lightburn/`，包括两份JSONL、`init-01-audit.json`、`init-02-audit.json`、截图、首版及修复版源码。审计独立检查TCP原始输入经白名单后与实际保留行的对应、GATT帧内容、真实接收序号/CRC/计数、全部真实终端的FIFO映射和TCP交付，无伪造ACK、无EOF后新增业务写。
