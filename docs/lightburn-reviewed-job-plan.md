# 待现场授权：同一零功率作业的 USB / LightBurn 原生 BLE 对照

## 范围

原有 USB、BLE 探针及 LightBurn 控制台运动授权均已执行完毕。本方案是新增两次固定作业：Pi USB 一次，Mac 上真实 LightBurn 经原生 BLE 一次。尚未执行，不因总体目标或离线测试通过而视为获准运动。

使用已审阅的 LightBurn 原生导出 `evidence/stream-transport/lightburn-zero-power-reviewed-v2.gc`，SHA256 `b2ef9334e8914688f5359c2b4e38faed071a602aafaceac531e04f1dd5d4a315`。具体 14 条指令见 [作业审阅](lightburn-zero-power-job-review.md)。每种后端仅一次 X 机器坐标 0→1→0 mm、60 mm/min，Y=400/Z=A=0 不变；初始 M5/S0，使用 M4 S0 模式，全程 S=0，无气辅指令。另有 G17/G40/G21/G54/G90/M2 等固定初始化和结束指令，完成后内部裸 G0 恢复快速模式。

现场须确认：激光模组供电仍物理隔离；X 正向 1 mm 净空；Y400 为当前实际位置，无其他轴移动需求；无人触碰设备；有人在现场且能独立断电。M4 S0 和两次作业运动均属于本次新增范围，不能沿用已消耗的剩余返程授权。

## 已准备的入口

- `tools/check_reviewed_job_host.py --backend usb`：默认离线。单独执行选项才允许固定 USB 作业；BLE 分支只能读取预检，不允许脚本代替真实 LightBurn 发作业。
- `tools/reviewed_job_bridge.py`：默认离线；执行须明确固定作业、隔离及新日志参数。127.0.0.1:4002、120 秒、总计仅一个 TCP 连接，固定指令顺序、有界队列。后续连接一律拒绝。
- `LaserLink NEJE5 Offline Review`：独立 260×400 mm、前左原点、自动回零关闭，最终原生配置包在 `evidence/stream-transport/neje5-review-final.lbzip`。原测试配置保留。

本次优先用 LightBurn 的“运行 GCode”加载这一个审阅文件，验证真实应用作业入口与真实完成反馈。文件哈希先核对，运行前后不编辑几何或图层。实际发送若与白名单不一致（包括未预见的实时控制、中文注释字节、重复提交、额外定位），关闭并保留证据，不能临场放宽范围。暂停、恢复、停止/取消按钮仍未授权作为主动控制实验，不点击它们；异常依靠现场独立断电及程序停止追加数据。

## 执行和停止规则

1. 先执行 USB 固定作业。每条真实应答入日志，逐条发送；完成后轮询 Idle 和 X0/Y400/Z=A=0，再读取模态确认 M5/S0，裸 G0，关闭串口。失败即不进入 BLE 对照，不自动返程，不重发任何可能已经被执行的行。
2. USB 成功且现场条件继续满足后，启动单次 BLE 桥接并打开真实 LightBurn。初始化仍仅 `$I/?/$#/G0`。第一条作业前内部读取 `$$/$G/$#/?`，确认设置、零偏移、G21/G90/G94/G54/M5/S0、Idle/FS0、起点。
3. 运行唯一固定文件。桥接逐条等待真实应答，校验 BLE CRC、连续序号及设备字节计数。内部查询的 ok 不交给 LightBurn，异步 MSG 完整转发；不给未发生的成功补响应。
4. 收到 M2 的真实 ok 仅表示控制器接受该行。桥接继续核验 Idle/终点与最终模态，日志出现 `job_completion_verified` 后才关闭 LightBurn。通道应关闭读回 way=0/app3；核对无未发送运动重放、TCP 及任务释放。

任意输入策略错误、设备 error/ALARM/重启、CRC/计数错误、超时、TCP EOF 或 BLE 断连均停止追加命令，丢弃未发送队列，拒绝重连续跑；不自动返程。实际断链可能使通道关闭无法确认，清理日志必须标为未知，必要时另行只读确认及显式关闭。关闭可靠通道不能证明已缓冲的运动停止。
