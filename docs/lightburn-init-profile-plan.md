# LightBurn 初始化兼容实验方案

最终目标仍为 Mac 原生 BLE 桥接达到 USB 操作效果。本实验只处理已观察到的初始化差异，不把初始化通过作为加工通过。

当前已验证的默认只读配置 `$I\n` / `?` 保留。新增独立、显式选择的 `lightburn-init` 实验配置，仅允许以下四个固定请求：

| 请求 | 性质 | 响应处理 |
| --- | --- | --- |
| `$I\n` | 固件信息查询 | 交付实际设备版本/选项及终结行 |
| `?` | 实时状态查询 | 交付实际设备状态 |
| `$#\n` | GRBL 参数查询 | 交付实际设备多行参数及终结行 |
| `G0\n` | 设置快速运动模式；不是纯读取 | 仅允许单独 G0，不允许坐标/速度/其他字词；交付该请求的真实终结行 |

G0 X1、G00、G0 S1、带注释/空格拼接、$H、$X、$J=、M3/M4、S、设置赋值、Ctrl-X 和其他内容均继续拒绝。拒绝明确标注为本地策略错误，绝不伪造成功。设置模式是实际状态变化，不能把新配置称作只读配置。

新增范围的实机执行需用户明确同意；沿用此前激光模组供电物理隔离的现场确认。先通过 Pi USB 对固定四条指令逐条取得真实基线，再做 Mac BLE 等价对照，最后用真实 LightBurn 验证初始化无本地拒绝错误。每轮有时间上限、设备身份/app3/空闲检查、通信计数/错误审计和 way=0 关闭读回。

后续加工阶段还必须独立验证通用传输、队列/流控、长时稳定、取消/急停与故障行为。当前配置没有开放加工，不自动续跑任务，不把 GATT 写返回或通信计数冒充 GRBL 执行完成。

参考：标准开源 [gnea/grbl system.c](https://github.com/gnea/grbl/blob/master/grbl/system.c) 的 $# 参数报告与 [gcode.c](https://github.com/gnea/grbl/blob/master/grbl/gcode.c) 的无坐标运动模式处理。标准代码不能代替 NEJE 固件实测；实现只依据协议事实独立编写，不复制 GPL 代码。
