# E56：二维零功率直线候选与开源几何对照

2026-10-12。二维文件审阅及USB/BLE候选已接入；本轮未打开串口、连接BLE、运动、出光或复位。整体工程估算仍约60%，最终USB等价目标仍进行中。

## 候选行为

文件入口新增显式`--file-profile xy-linear-zero`，默认仍为原有一轴范围。二维审阅使用G21/G90/G94/G54、零偏移、起止X0/Y400/Z0/A0、S0、F≤60，允许G1及其模态继承，X在0..260、Y在0..400机床范围内；从线段顶点计算文件实际包围盒及欧氏长度。运行时按该文件包围盒同时核验X/Y及固定Z/A，最终Idle必须回到X0/Y400，再完成私有模态/裸G0/模态核验。

执行二维候选除文件摘要和现有独立文件/控制/隔离门槛外，还必须有`--allow-reviewed-xy-file`。旧一轴开关不能自动扩大为Y轴运动；缺少新范围时，在创建日志或导入硬件模块前拒绝。本轮没有获得或使用新增二维运动授权。USB二维文件目前仅正常完成；BLE文件沿用独立控制门槛。文件包围盒不是碰撞检测或现场净空确认。

目前仍拒绝移动G0、G2/G3、G20/G91、非零功率、其他轴及坐标/设置写入；因此尚未覆盖LightBurn的多轮廓快速定位、通用圆弧、相对坐标或实际加工流程。源命令按原字节传输，不自动改写、线性化或插入返程。本轮同时修复审阅器将CRLF转换为LF的问题；LF/CRLF均原样保留，单独CR行结束被拒绝，并完成两种换行的USB/BLE模拟及审计。

## 开源借鉴与独立核验

采用[cncjs/gcode-toolpath](https://github.com/cncjs/gcode-toolpath)的初始坐标、模态、线段/圆弧回调作为独立几何参照。已归档MIT版gcode-toolpath 3.0.0、gcode-interpreter 3.0.0、gcode-parser 2.2.0的原始npm包、元数据、许可证及解包源码，并逐包核验registry SHA-512 integrity。固定的是包版本及散列，元数据没有gitHead，不声称固定了对应Git提交。Python硬件桥接没有新增Node运行依赖；开源包只用于离线几何对照。

`tools/check_xy_geometry_oracle.cjs`从X0/Y400初始位置解释文件，输出线段、顶点、边界和长度。34份直线文件（两份运行候选及32份确定性生成的几何语料）的顶点/包围盒一致，距离差小于1e-8 mm。随机语料只用于几何核验，部分总路径超过执行时限，不是获准硬件作业。该解释器对未知指令的处理不是我们的授权规则；输入门控仍由已有严格审阅负责。

同时归档固定[gnea/grbl解析源码](https://github.com/gnea/grbl/blob/bfb67f0c7963fe3ce4aaf8a97f9009ea5a8db36e/grbl/gcode.c)及许可证，用于后续圆弧研究。这是上游参考，并非NEJE固件逐字节等价证明。已保存反例：G2从(0,400)到(10,400)，I5/J0，端点都在工作区，但顺时针上半圆到Y405。不能仅靠端点包围盒判断圆弧；现有线性候选会拒绝它，参考工具也明确标记圆弧边界未完整计算。

完整回归225项通过（36.910秒），新增6项；其中33份文件参与单元差分核验，独立采集又加入25mm候选，合计34份原始几何证据。

| 10×10mm闭合轮廓 | 11 | 40mm | 0..10 / 390..400 | 两路独立审计通过，模拟顶点及命令相同 |

最终源码采集位于`captures-final/`，早期同范围模拟保留在`captures/`。证据：[evidence/xy-linear](../evidence/xy-linear/)，含候选文件、两路原始捕获及审计、34份几何对照、圆弧反例、开源包及散列、测试、源码快照。整体权重由58/100调整到60/100，可复用传输12→14；对外估算仍约60%，实机控制/故障/加工得分没有增加。
