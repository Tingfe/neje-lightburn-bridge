# 图片无动作及 Stop 关闭桥接：诊断与修复

2026-10-14。用户反馈图片 Start 完全没有动作、LightBurn Stop 会结束桥接，并提供当前 LightBurn 工程。设备本轮不在旁边，全部新增验证为文件、真实软件 UI 和模拟传输；没有设备连接、运动、出光或复位。

## 当前图片的确切原因

原图为 330×115 的 RGBA PNG，8508 个可见像素全部为 RGB(254,254,254)，另有29442个完全透明像素。这是一张接近纯白的透明标志。正常图像设置下，实际 LightBurn 2.0.05 导出的 `user-image-original.gc` 只有177字节，边界为 `X0 Y0 to X0 Y0`，没有图像扫描路径。对当前提供的工程，空作业在 LightBurn 导出阶段就已形成，不能据此判断桥接拒绝图片。

在 C00 切割设置编辑器开启“负片图像”，保持输出开启，未修改原 PNG、速度、功率、气辅、尺寸或放置。工程中已有两个图片对象均保留。真实预览显示标志和文字，透明区域未成为实心矩形；切割距离2353mm、快速移动6830mm、估计3分12秒。预览窗口的“反转”是显示选项，与图层“负片图像”不同。

修正后实际导出 `user-image-negative.gc`：43942字节、3934行，边界 `X27.04 Y195.6 to X146.33 Y351.9`。执行行含 G0、G91/G1 扫描、S0/S200 和 M4；原工程为6000mm/min、20%功率、气辅开启，**不是零功率文件**。修正工程 `user-image-corrected.lbrn2` 已保存并留在 LightBurn；原 PNG 无写入。

离线发送器剔除导出用分号注释后，按120字节批次及实际终端应答发送3928行／43753字节，通过真实 loopback TCP、NEJE 编码/CRC/滚动计数和假 BLE 控制器。发送顺序与来源逐字节一致，3916条 G1、1688条带正功率参数行的传输、终端归属及way0清理通过独立审计。没有真实扫描动作或成品证据。第一次把整个导出一次发送的辅助脚本失败，以及之后错误假定 EOF 会额外发送查询的核验失败，均保留 stderr；修正的是离线发送器和其预期，桥接没有为此删除注释或改写输入。

此设置仅解决当前白色透明标志；不能对所有照片默认负片。以后遇到“完全无动作”，先看预览和导出是否存在有效路径，再核对图层输出、控制器 Alarm/位置基准和会话日志。

## Stop 的兼容修复

用户既有 `18:46` 和 `18:59` 会话日志显示：设备复位后真实 Alarm/Idle 已确认，旧实现随后记录 `controlled_session_cancelled`、关闭way0并结束监听。它把“结束作业”同时当成“结束桥接”，符合旧受限实验的恢复规则，却不符合原生 LightBurn 的持续连接使用方式。

透明模式现在只结束旧作业代际：Stop 优先废弃未发送行，真实横幅使在途账本失效；新鲜 Idle/Alarm 确认后保持 TCP/BLE 链路，接受同一连接上的新初始化。横幅先处理再交付给 LightBurn，避免它立即发 `$I/$G` 时仍撞上旧输入锁。新查询在确认前排队，旧作业绝不重放，不制造其 `ok`，不主动解锁/回零/返程。坐标仍标为不可信，需操作者显式恢复基准。受审实验模式继续维持原来的复位结束会话规则。

连续两次 Stop→立即 `$I/$G` 已在同一 loopback TCP 和同一个假 BLE 实例通过，审计核对真实模型横幅/状态/应答归属、源字节、旧行废弃及两个代际；篡改“位置可信”或伪造应答时审计拒绝。另以延迟应答模型验证旧半行已发送、旧队列未发送的情况下，新查询必须等待新状态，不追加旧半行；缺横幅、横幅后缺 Idle/Alarm 仍故障，不推定成功。软件停止也使用所属连接，GUI 分开显示请求提交与设备状态确认。

## 状态计数超时

既有 `18:57` 会话还暴露了状态账本问题：设备真实状态仍到达，旧实现却保留多个无对应报告的查询额度，最后状态超时。GRBL 官方 `serial.c` 将 `?` 表示为 `EXEC_STATUS_REPORT` 位标志，`protocol.c` 消费该标志；连续多个问号可以合并成一个报告，并非必然一问一答。

透明模式正常运行时保留一个待状态报告的截止时间，后续真实问号仍原字节发送，但不追加虚假的应答债务。收到真实报告才释放；后续问号不会延长最初的8秒超时。私有复位状态确认继续保持独立屏障。模拟三次实际问号合并成一份报告通过；同一批次返回多份真实报告也完整透传，不重复扣除查询额度。复位前旧报告不构成停止确认，未匹配的额外报告不能作为GUI自动重连依据；完全无报告时仍按原截止时间失败。真实 `error:9` 保留为设备错误，不被桥接改成成功。

借鉴依据：[GRBL serial.c](https://github.com/gnea/grbl/blob/master/grbl/serial.c)、[protocol.c](https://github.com/gnea/grbl/blob/master/grbl/protocol.c)、[官方字符计数流控示例](https://github.com/gnea/grbl/blob/master/doc/script/stream.py)及 [LightBurn 图像设置](https://docs.lightburnsoftware.com/latest/Reference/CutSettingsEditor/ImageMode/)。独立实现，没有复制 GPL 运行源码。
