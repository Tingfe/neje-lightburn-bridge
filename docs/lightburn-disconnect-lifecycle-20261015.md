# LightBurn 断开后桥接继续待命：1.2.3 修正

2026-10-15。用户指出 LightBurn 断开设备后桥接端口也关闭，不符合“图形程序退出才结束桥接”的日常使用预期。本轮只读分析既有日志、修改源码并进行离线验证；没有连接或控制真实 NEJE，也没有替换当前运行的应用。

## 真实触发与原因

09:20–09:42 的 1.2.1 会话中，LightBurn 于 09:42:08 正常 TCP EOF。日志记录在途应答清空、`cleanup_verified`、BLE 断开、`cleanup_unknown=false`、`failure_reason=null`。该会话此前发生两次已确认 Stop／复位。旧审计把“曾发生过复位”一律当作禁止自动再开连接的条件，图形监督器因此在 09:42:09 记录“自动重连已禁止”，4002 监听随单次会话结束。原始会话仍保留在本机 `~/Library/Logs/NEJE/neje-20261015T092020242672.jsonl`；本轮分析摘要见 `evidence/lightburn-disconnect-20261015/`。这解释了本次关闭，并不表示 GUI 本身退出或设备在断开时停止。

## 新行为与边界

1.2.3 在正常 TCP EOF、旧命令和真实应答已排空且没有未发送作业/控制字节时，额外发送**一条内部只读 `?`**。只有真实报告为 `Idle` 且 `FS:0,0`、原始帧审计和 `way=0` 清理全部通过，图形程序才自动准备下一条独立 BLE/TCP 会话。它不会重放命令、自动回零、恢复位置或把断连当作停止。已有 Stop 历史不再单独阻止重新建立**通信**，但 GUI 会提示操作者复位后坐标仍不可信。

若断开时仍在运行、旧数据/应答未排空、查询超时、控制器报警、无线失联、清理或审计不完整，自动准备新会话仍被禁止，界面要求检查设备并显式重新连接。关闭桥接或退出 GUI 会终止所属桥接进程及监听；已缓冲的设备动作可能继续。每个底层会话仍只接受一个 LightBurn TCP 客户端，CLI 一次性模式不变。

## 验证与待办

真实 NEJE 原始捕获只用于定位 1.2.1 原因，不能证明 1.2.3 的新行为已在硬件上通过。新增离线测试覆盖 Stop 后正常 EOF、短会话迅速再待命、真实 Run 状态拒绝自动重连、伪造断后 Idle 记录拒绝审计。**465 项全量离线回归通过**。下一次现场应使用 1.2.3：空闲时在 LightBurn 断开、重连两次，核对 GUI 持续待命与新连接初始化；另做运行中断开，确认不得自动接续。两个路径均需保留原始日志并核对清理，不能仅凭窗口显示判断。

整体目标估算仍约 **94%**：修复已离线验证，真实软件包与实机重连仍需独立验收。
