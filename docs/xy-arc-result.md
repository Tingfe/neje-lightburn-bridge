# XY圆弧零功率候选与离线对照（E58）

2026-10-12。新增显式`xy-arc-zero`文件审阅及USB/BLE传输候选，支持G17平面G2/G3、相对圆心I/J、正负R及带轴字的I/J整圆。默认仍为原一轴直线范围；本轮未连接NEJE、未打开串口、未运动、未复位。现场确认“两次均暂停后恢复并返回，无其他轴异常、无出光”已经保存在E52观察证据和[实测报告](controlled-job-parity-result.md)，不是本轮新动作。

## 实现与开源依据

以固定提交[gnea/grbl的解析器](https://github.com/gnea/grbl/blob/bfb67f0c7963fe3ce4aaf8a97f9009ea5a8db36e/grbl/gcode.c)、[圆弧执行语义](https://github.com/gnea/grbl/blob/bfb67f0c7963fe3ce4aaf8a97f9009ea5a8db36e/grbl/motion_control.c)及[配置](https://github.com/gnea/grbl/blob/bfb67f0c7963fe3ce4aaf8a97f9009ea5a8db36e/grbl/config.h)为研究依据，用已固定包版本的[cncjs/gcode-toolpath](https://github.com/cncjs/gcode-toolpath)作独立圆心/方向参照。源码、包、许可证、URL和散列均归档。固定上游不是NEJE固件等价证明，仍需设备曲线对照。

`tools/reviewed_arc_geometry.py`计算圆心、方向、弧长和整个扫角内的极值，结合直线段形成文件包围盒；不能只看起终点。已实际拒绝端点(0,400)→(10,400)均在行程内、顺时针却达到Y405的反例。I/J半径一致性采用上游容差，允许微小不一致时扩大到较大半径作保守包络；这不是对实际固件插补误差的量化。源码中的`5e-7`弧度阈值会把接近零的扫角判成整圆，已单独验证，避免误算为几乎零距离。

本候选仍限S0、F≤60、X0..260/Y0..400，起终点X0/Y400、Z/A0；只允许G17平面、毫米、绝对轴坐标和每分钟进给。G91.1仅声明相对I/J圆心，不开放G91轴相对移动。保守限制圆弧半径0.01..10000mm；混用R和I/J、缺少圆心、零半径、R小于半弦、半径不一致、未声明G17、其他轴和非零功率均拒绝。移动G0仍拒绝。

命令保持原字节，不线性化、不改写、无补发返程；LF/CRLF均保留。距离和活动时限计入弧长。原有摘要锁定、流控、响应归属、终点及私有$G/G0/$G收尾共用；独立捕获审计必须核对圆弧文件摘要、profile和完整包围盒。修正USB准备日志原来固定写X0..10的问题，改为如实记录受审文件X/Y边界。

执行除既有文件、二维、控制、隔离及摘要门槛外，还需`--allow-reviewed-arc-file`，在导入硬件和创建日志前检查。旧一轴/二维开关不能启用圆弧。CLI参数是执行范围约束，不能替代现场授权；本轮没有获得圆弧现场授权。USB文件仍仅正常完成，运动中取消仍使用单独固定方案。
