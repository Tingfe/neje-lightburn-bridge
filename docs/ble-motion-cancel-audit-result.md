# E66：USB／BLE 运动停止审计补齐与当前基线准备

2026-10-13。上一轮E65为实质进展：原生曲线USB／真实LightBurn BLE各一次实机及现场观察通过。本轮完成停止审计工具和当前Pi候选准备，未打开串口、连接设备BLE、执行运动或复位。整体目标保持约65%（64/100）；没有把模拟停止计入实机控制验收。

## 具体改动

`tools/check_motion_cancel_capture.py`原先只支持USB，现保留默认USB并新增 `--backend ble`。同一固定14行／144字节作业范围，未扩大运行入口、白名单或设备控制权限。BLE审计重新解析实际TCP输入和初始化命令、普通行账本、真实终端归属、复位前Run/X2–8、新启动行使在途序列失效、复位后状态及本机废弃；随后利用既有原始通知／CRC／可靠发送计数审计核验无线传输和way0/app3清理。

真实LightBurn初始化ACK和作业ACK分别计数，不能把初始化成功当作作业成功。本轮BLE模拟包含3条初始化及14条作业：16条普通行ACK中13条为作业ACK，最后作业序列17由真实模拟启动行失效，没有给它补一个ok；最终Alarm或Idle均保持job_completed=false、position_trusted=false。审计输出的最终状态必须与最后实际原始状态一致，不能只信总结事件。控制器模拟和全部轨迹显式标记simulated，不允许默认当实机捕获通过。

`tests/test_controlled_tcp.py`的Bleak模拟补齐退出时调用实际构造参数中的disconnected_callback，模拟框架与实际生命周期一致。新增4项BLE审计测试覆盖初始化/终端账本、原始通知/公开ACK/失效序列/总结状态/关闭篡改、复位接受后断链拒绝成功及复位后Idle不等于作业完成。运行核心未改动，没有增加自动重连或恢复。

## 验证及证据边界

定向BLE4项、已有USB停止4项均通过。完整244项回归通过，43.960秒。首次定向检查发现旧模拟未触发断开回调，2项被严格审计拒绝；修正模拟生命周期后通过，失败记录保留。没有用删除实际断开检查来让测试变绿。

归档USB停止、BLE停止Alarm、BLE停止Idle三份模拟捕获及独立成功审计；另有“复位已接受后断链”捕获，成功审计明确拒绝，cleanup_unknown=true，不重试。模拟使用真实回环TCP和NEJE分帧/CRC/计数实现，不能替代真实LightBurn界面Stop、物理停止距离、NEJE复位语义或真实无线链路故障。

沿用已固定的gnea/grbl上游命令/接口及simple_stream.py、stream.py，和cncjs控制器/许可证，共6份既有原始文件重新核验摘要。强调普通ACK账本、实时复位与新会话状态分开处理，不重写已有流控。记录位于open-source-references.json，源URL和原有SHA保留；本轮读取归档主源，没有重新联网获取或假定NEJE固件与上游完全相同。
